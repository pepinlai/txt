# 小說 YouTube 趨勢儀表板

當使用者說「找小說」，或要找、比較、評估網路小說，尤其提到「爆款」、「YT／YouTube 趨勢」或「小說短劇選題」時使用。目標是幫使用者為 **原創** 短劇選題建立可回看、可比較的資料庫；不是代替授權，也不是把原作直接改編成影片。

## 先做趨勢驗證

每一批小說前先研究 YouTube 當日的公開搜尋結果，再找書和評分。預設涵蓋下列六組，並以本次題材加深研究：

- 古今互通／物資／兩界
- 系統／逆襲／重生
- 大女主／流放／經營
- 商業／投資／職場創業
- 透視眼／鑑寶／賭石超能力
- 機甲／星際／軍工科技

保留可見的影片標題、頻道、觀看數、發布時間、搜尋日期與搜尋詞。使用 4～8 個近期案例即可；它們只能作為抽樣信號，不能描述成全站排行榜，也不能從公開數據斷定性別或其他個人受眾資料。

先寫出「本批的趨勢結論」：哪些高概念正在起量、哪些擁擠、哪些製作成本偏高，並讓這些觀察明確反映在個別評語與分數中。

## 尋書與評估

除非使用者明確指定別的數量或單一類型，使用者說「找小說」時提供 60 本。預設六組各 10 本：古今互通／資源經營、系統／重生／末日逆襲、商業／投資／職場創業、透視眼／鑑寶／賭石超能力、機甲／星際／軍工科技、大女主／流放／懸疑泛受眾。當日趨勢明確偏向某類時，可調整數量並解釋原因。優先採用番茄、七貓公開作品頁。

每本必須包含：來源連結、1～2 句摘要、分類、標籤、目標受眾、AI 製作難度、10 分制爆款潛力與正反評語。評分依序檢查：前 30 秒危機或反差、持續升級／任務、情緒回報、標題與縮圖可懂性、Pippit 的製作穩定度、差異化。

分數只是理性預估，不能承諾爆紅。須把慢開場、同質化、爽點太晚、角色／場景／特效成本、標題難點擊或受眾過窄等風險說清楚。

## 累積儀表板

唯一資料庫是：

`/Users/pepin/Documents/ChatGPT/小說視頻/30本小說YT爆款評估_閱讀版.html`

每次完成一批 60 本時，在同一份 HTML 新增一個有日期的研究批次；保留舊資料，不用新檔覆寫。資料要以頁籤呈現：全部小說、熱門題材、最新收錄、舊資料與各題材分類。最新收錄＝最新研究批次；舊資料＝先前批次；熱門題材＝當期 YouTube 趨勢信號加上高分評估，不能稱為原著平台排行榜。每張卡片用優先研究／值得追蹤／僅取元素和色標清楚顯示分數。儀表板要顯示總收錄數、平均分、高潛力（≥8.5）數、分類分布、近期 YouTube 快照與批次紀錄，並保留「再找 60 本」的入口。資料新增後，驗證完成便部署到使用者已連接的 GitHub Pages；先確認遠端與 Pages 設定，若缺少設定則回報，不假裝已部署。外部瀏覽器受本機檔案安全政策阻擋時，回傳可點擊連結，不使用窄欄預覽替代。

同作品再次出現時，保留舊紀錄並標記為重複追蹤。只有趨勢、作品狀態或評估理由實質改變時，才新增新版紀錄，且指出變動原因。

## 網站實作與安全

GitHub Pages 僅部署公開前端，不能保存任何模型金鑰。需要使用按鈕自動查 YT、找 60 本或生成稿件時，使用受保護的 Cloudflare Worker API；OpenAI API Key 僅放在 Worker secret，前端以使用者輸入的 Dashboard Access Key 呼叫。研究結果在同一瀏覽器的資料庫累積，成功後立即重算統計、更新批次、標示最新收錄，並允許 TXT 匯出。

生成按鈕的含義固定為「從類型評估訊號創造獨立原創劇本」，不是對原作的改寫、後續、補全或仿作。

## 版權邊界

小說僅作題材結構與節奏研究。公開製作前，重新設計書名、角色、道具規則、世界觀、衝突與分集事件；不可複製原文、逐章重寫或將未授權作品直接做成影片腳本。
